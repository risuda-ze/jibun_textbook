# 仕様レビュー観点

## 市場
| # | 観点 | 確認方法 |
| --- | --- | --- |
| M1 | 配信者・チームのどの困りごとを解消するかが明確か | 目的の記述と `docs/仕様・計画/risukeru_gg_事業計画_1.md` 3章「取扱商品・サービス」の整合 |
| M2 | 既存機能と目的が重複していないか | 正本仕様の機能要件一覧と照合 |
| M3 | 課金との関係が妥当か（無料で提供して収益を毀損しないか、有料限定で価値が伝わるか） | `docs/仕様・計画/plan/*` と事業計画 7章「事業の見通し」 |
| M4 | フェーズ 1 スコープ外（正本仕様末尾）に該当していないか | `risukeru_gg_spec.md`「フェーズ 1 スコープ外」 |

## アプリ制約
| # | 観点 | 確認方法 |
| --- | --- | --- |
| A1 | 正本仕様の該当節と矛盾しないか。矛盾する場合、仕様変更として明示されているか | 参照節を読む |
| A2 | NFR-005/006（チーム分離・ロール権限のサーバー強制）を満たすか | 対象者・制約の記述 |
| A3 | NFR-011（プラン制限はバックエンド強制）に抵触しないか | 課金・上限の記述、`functions/src/plan` |
| A4 | NFR-010（JST 基準）を破らないか | 日時を扱う受入条件 |
| A5 | 外部サービス（Discord / Stripe / メール / Google カレンダー）失敗時の扱いが書かれているか。失敗を握りつぶす仕様になっていないか | 制約・注意 |
| A6 | NFR-001/002（表示・応答性能）、NFR-008（対応ブラウザ）、NFR-009（アクセシビリティ）に影響する変更なら考慮があるか | 対象範囲 |
| A7 | 用語が `docs/共通用語/共通用語.md` と一致しているか | 用語追加候補の有無 |

## 実装性
| # | 観点 | 確認方法 |
| --- | --- | --- |
| I1 | 受入条件がすべて観測可能で、ユニットテストまたは手動手順に落とせるか | 受入条件表 |
| I2 | 影響範囲が過小評価されていないか（呼び出し元・Functions・Firestore ルール・型定義） | `src/` `functions/src/` を grep |
| I3 | 対象範囲の「含まない」が境界として機能するか | 対象範囲 |
| I4 | 段階的に出せる分割点があるか（あれば参考として記す） | 受入条件の依存関係 |
