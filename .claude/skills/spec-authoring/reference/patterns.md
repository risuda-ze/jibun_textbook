# 複数案の設計軸（自律型）

課題に合う軸を 1〜2 つ選び、2〜4 案に分ける。案の名前は軸の値で付ける（例: 「最小案」「標準案」）。

| 軸 | 値の例 | 使いどころ |
| --- | --- | --- |
| 規模 | 最小（既存 UI 流用）/ 標準 / 拡張（新画面・新エンティティ） | ほとんどの機能追加 |
| 実現層 | クライアントのみ / Functions で強制 / 外部サービス連携 | 制限・通知・課金が絡むとき |
| 対象者 | 本人のみ / チーム全員 / ロール別 | 権限が絡むとき |
| 既存との関係 | 既存機能を拡張 / 別機能として追加 / 既存を置き換え | 似た機能があるとき |
| 課金 | 全プラン / 有料プラン限定 / 上限つき | プラン制限に触れるとき |

## 各案に必ず書くこと

- テンプレート全項目（受入条件の粒度を案間で揃える）
- 利点・欠点・影響範囲（ファイル数・レイヤー数）・既存仕様との整合
- 置いた仮定

## 推奨の書き方

推奨は 1 案。理由は「課題の解消度」「影響範囲」「既存仕様との整合」の 3 点で述べ、判断はユーザーに委ねる旨を添える。
