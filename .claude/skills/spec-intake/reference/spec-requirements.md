# 変更仕様の必須項目

実装に渡す変更仕様は以下をすべて含むこと。1つでも欠けていれば受け入れず、ユーザーに不足を返す。

| 項目 | 必須内容 | 不足と判断する例 |
| --- | --- | --- |
| 変更名 | 一意な名前 | 無記載 |
| 目的 | 何のために変えるか（1〜2文） | 無記載 |
| 対象範囲 | 含む機能・画面・API と、含まないもの | 「関連箇所も適宜」など境界が不明 |
| 正本仕様との関係 | 参照する `docs/仕様・計画/*` の節。仕様変更の有無と、ありの場合の変更内容 | 参照先が無い／仕様変更の有無が不明 |
| 受入条件 | ID 付きで「入力・操作 → 観測できる結果」。曖昧語（適切に・正しく・ちゃんと）を含まない | 期待結果が観測不能／曖昧語を含む |
| 影響ファイル（想定） | `src/` `functions/src/` `tests/unit/` の想定パス | 対象範囲が明確なら無記載でも可（実装側が特定する） |
| 制約・注意 | 権限・プラン制限・JST・外部 API 失敗時の扱いなど、該当するもの | 該当するのに無記載 |

## 受入条件の書式

| ID | 入力・操作 | 期待結果 |
| --- | --- | --- |
| AC-1 | 例: 無料プランで月次上限ちょうどのタスクがある状態で新規作成する | 例: 作成が拒否され、上限到達のメッセージが表示される。Firestore に書き込まれない |
