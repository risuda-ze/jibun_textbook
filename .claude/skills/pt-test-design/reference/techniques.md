# PT工程テスト技法

受入条件の性質に応じて技法を選ぶ。1つの受入条件に複数の技法を使ってよい。

| 受入条件の性質 | 技法 | 導出手順 |
| --- | --- | --- |
| 入力値に範囲・分類がある | 同値分割 | 有効同値クラス・無効同値クラスを列挙し、各クラスから代表値を1つ選ぶ |
| 上限・下限・件数制限がある | 境界値分析 | 境界そのもの、境界−1、境界+1 の3点を各境界で取る（例: プラン月次上限 N なら N−1 / N / N+1） |
| 複数条件の組み合わせで結果が変わる | デシジョンテーブル | 条件を列挙し、Y/N の全組み合わせと期待動作を表にする。到達不能な組み合わせは理由付きで除外 |
| 状態を持つ（タスク列・スケジュール・課金状態） | 状態遷移テスト | 状態と遷移イベントを図にし、全遷移を1回ずつ通す。無効遷移（許可されない状態からの操作）も含める |
| 過去の不具合傾向・実装者が見落としやすい点 | エラー推測 | null / undefined / 空配列 / 空文字 / 全角空白 / 日付境界（JST 0時・月末）/ 権限なし / 二重送信 |

## 定例で必ず含める観点

- 権限: 本人・チームメンバー・無関係ユーザー・未ログイン の各立場で操作した場合
- プラン制限: 制限内・制限ちょうど・制限超過（バックエンドで拒否されること）
- 時刻: JST 基準の日付境界をまたぐ入力
- 失敗経路: 外部 API（Firestore / Discord / Stripe / メール）失敗時にエラーが可視化されること
