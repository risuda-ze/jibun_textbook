# 変更単位の分割基準

## 分ける条件（すべて満たす場合のみ分ける）

- 受入条件の間に依存が無い（一方の結果を他方の前提にしていない）
- 影響ファイル（想定）が重ならない。重なる場合は同じ単位にする
- 正本仕様の同じ節を変更しない
- 単位ごとに typecheck / lint / test が単独で緑にできる（共通の型定義や共有関数を先に作る必要があるなら、それを先行単位にする）

## 分けない条件（1つでも該当したら 1 単位にする）

- 受入条件が 3 件以下
- UI とその裏の Functions / ストアが 1 つの操作で結び付いている
- 影響範囲が推定できず、分割の妥当性を判断できない

## 単位の順序

- 共有の型・ストア・Functions の基盤を作る単位は先行させ、完了後に依存する単位を起動する
- それ以外は並列に起動する

## 記録項目

| 変更単位 | 担当する受入条件 ID | 影響ファイル | 先行単位 | 起動順（並列 / 直列） |
